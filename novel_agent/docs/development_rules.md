# Development Rules

## 通用性约束

本项目开发的是通用的自动小说创作/续写助手，不是针对某一部小说的定制工具。

不得在代码、prompt 模板、fallback 逻辑、默认词典、别名表、白名单、标签规则、测试默认数据中写入只适用于某一部具体小说的专有名词、角色名、设定名、桥段偏好或语义映射。

如果某个需求看起来需要通过针对当前样例小说写死关键词或规则才能满足，必须先尝试将它抽象为适用于所有小说的通用能力，例如：

- 从当前作品的输入文本、记忆库、角色档案或用户配置中动态抽取。
- 通过模型或通用规则生成 book-scoped 数据，而不是写入全局默认值。
- 使用通用分类、结构字段或可配置 taxonomy 表达。
- 在测试中使用中性虚构样例，避免绑定真实作品专名。

如果无法合理抽象为通用能力，应暂停实现该 hardcode，并说明：

- 该需求为什么依赖某部作品的特殊内容。
- 它会如何影响其他小说。
- 是否应调整需求、产品方向，或改为显式的用户配置/项目配置。

## 审查重点

涉及以下位置的改动需要额外检查是否引入作品专属规则：

- prompt 示例、system prompt、user prompt、schema 示例。
- dry-run、fallback、mock、seed、default 数据。
- 分词词典、人物名白名单、停用词、别名映射。
- 内容标签、世界观分类、剧情结构分类、检索 rerank 规则。
- 单元测试中的默认小说名、角色名、设定名和桥段样例。

允许出现具体作品内容的情况仅限于当前 book 的输入、用户显式配置、数据库中的 book-scoped 数据、测试夹具中明确标注为局部输入的数据。即便如此，也不得把这些内容提升为全局默认规则。
